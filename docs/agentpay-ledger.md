# AgentPay 与防篡改精算台帐

## AgentPay（AI 代理支付授权）
- 空间的 owner 在 `/my/agents` 给 AI 代理发行授权，可以设置：
  - 名称
  - 月预算、单笔上限
  - 允许购买的应用（全部或指定几个）
  - 有效期（1〜365 天）
  - 权限：只能搜索（`catalog`），或也能购买（`subscribe`）
- 发行时显示一次 API key（`msk_…`），数据库只存哈希。owner 随时可以撤销，撤销后立即失效。
- 代理 API：
  - `GET /api/agent/v1/mandate`：查看授权内容和剩余预算
  - `GET /api/agent/v1/apps`：搜索允许购买的应用
  - `GET /api/agent/v1/subscriptions`：查看空间当前的订阅
  - `POST /api/agent/v1/subscriptions`：开通应用
- 购买流程：
  1. 锁住这条授权，检查单笔上限、月预算、应用范围、价格版本是否一致、空间是否登记了卡，然后先记一条「处理中」的交易。这样并发请求也不会超出预算。
  2. 以 `agent:<授权ID>` 的身份走正常的申请和信用卡支付流程。
  3. 记录结果：批准、拒绝或失败，拒绝和失败都写明原因。
- 代理买的付费套餐默认不开启自动续费，需要的话由 owner 在合同页打开。
- 同一个 `idempotency_key` 重试会返回同一个结果，不会重复购买。
- 代理不能购买「要咨询」的套餐。

## 防篡改精算台帐（链上结算的基础）
- 定时任务把以下资金事件按发生顺序追加到哈希链：入账（月费、AI 按量费、信用卡扣款都算）、退款、向提供商的付款。
- 每条记录的哈希 = `sha256(上一条的哈希 + "\n" + 规范化 JSON)`。只追加，不修改；同一事件因 `(kind, refId)` 唯一，不会重复写入。
- 链头有变化时生成锚点（链头哈希）。
- `/admin/ledger` 从第一条开始重新计算整条链，能指出第一处被篡改的位置；可以导出 JSON，第三方按同样的规则就能独立验证。
- 未做：把锚点写入区块链或对外发布。现在锚点的写入目标统一记为 `none`，页面上也写明「未连接区块链」。真要上链，需要确定用哪条链、托管哪把密钥、手续费谁承担，再加一个把锚点写上去的组件；台帐的数据结构不用改。

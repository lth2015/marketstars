# P1 功能说明

## 在线支付与自动续费
- 付费套餐申请时可选「信用卡」或「请求书払い」：
  - 选信用卡：支付成功即刻开通，从支付时刻起算 1 个月，默认开启自动续费。
  - 选请求书払い：沿用 P0 流程，等运营确认收款后开通。
- 支付服务商通过 `src/lib/payments/provider.ts` 抽象接入。demo 用的是 `mockpay`，测试卡如下：

  | 卡号 | 结果 |
  | - | - |
  | 4242 4242 4242 4242 | 成功 |
  | 4000 0000 0000 0002 | 拒绝 |
  | 4000 0000 0000 0341 | 可以登记，但扣款失败 |

  正式环境要换成真实的支付服务商：卡号只在服务商的页面或 SDK 里输入，MarketStars 只拿令牌，不经手卡号。
- 防重复扣款：每笔收款都对应一个 `PaymentIntent`，有唯一的 `idempotencyKey`；扣款前用条件更新把它置为 `processing`；服务商侧也使用幂等键；`BillingRecord.receiptRef` 存放的扣款 ID 有唯一约束。
- 自动续费（定时任务 `renewDue`）：
  - 本期结束前 24 小时开始扣款。成功则从本期结束时刻起再延长 1 个月。
  - 失败最多重试 3 次，每次间隔至少 6 小时。期末前仍未付清，就按 P0 规则到期，不会先给后面的周期权益。
  - 同一周期的幂等键固定为 `renew:<订阅ID>:<本期结束时间>`，所以多副本同时执行、重复执行都只会扣一次。
- 支付服务商的异步通知走 `POST /api/v1/payments/webhook`，用 HMAC 签名校验，结算可以重复调用。
- 用户可以在 `/my/billing` 管理卡片。正在给某个订阅自动续费的卡不能删除。

## 套餐自助变更
| 当前状态 | 变更方式 |
| - | - |
| 付费使用中 | 换成其他付费套餐或免费套餐，本期结束时生效，不按天折算，期末前可以取消 |
| 免费使用中 | 升级到付费套餐，用信用卡支付后立即生效 |
| 试用中 | 用信用卡支付立即转为付费；选请求书払い则进入运营的申请处理队列，需要在试用期内完成收款确认 |

价格以变更时的现行价格版本为准，服务端会重新核对。

## 评分评论
- 只有在当前空间里实际用过该应用的成员（试用、免费或付费开通过）才能写评论，每人每个应用一条，可以修改。
- 详情页显示评论和平均分，应用卡片在有评论时显示评分。
- 平均分只按公开的评论计算。运营可以在 `/admin/reviews` 隐藏或恢复评论，开发者可以回复。

## 开发者自助提交与审核
- `/developer`：空间的 owner 登记成为开发者后，这个空间就是对应的提供商。
- 开发者可以新建应用、编辑草稿（包括套餐提案），然后提交审核。审核中不能编辑，可以撤回提交。
- 运营在 `/admin/submissions` 里预览并审核：
  - 批准后立即发布，套餐提案转成新的价格版本，已有订单保留原价格快照。
  - 驳回时必须写理由，开发者能看到。
- 已发布的应用再修改也要重新审核，审核通过前线上内容保持不变。
- 接 SSO 用的 client ID 和 secret 由运营发放，开发者不能自己设置。
